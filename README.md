# QDebit

Дебит скважины (замер ведром, серии, история) + модель скважины + подбор насоса.

**Онлайн:** https://q00000p.github.io/QDebit/ — веб-версия, ничего ставить не нужно, данные хранятся в браузере.
**Android:** APK в [Releases](https://github.com/Q00000P/QDebit/releases) (Android 8+).

Что умеет: замер дебита ведром сериями с оценкой погрешности; профили скважин (обсадная на песок/известняк, абиссинка, колодец) с геологией и разрезом; модель скважины s = B·Q + C·Q² по замерам, в том числе без уровнемера — по манометру на запечатанной скважине; подбор и проверка насоса по каталогу из 879 моделей (погружные, поверхностные, эжекторные) с трением, NPSH и реле; план участка на спутнике Google/Яндекс с расстояниями, отметками и профилем-разрезом (Android); синк и Grafana через InfluxDB (Android).

Каталог собран из паспортных таблиц и графиков производителей; часть моделей — по паспортным числам («≈ кривая», помечены). Результаты — инженерная оценка, перед покупкой насоса сверяйся с паспортом.

Лицензия — MIT (`LICENSE`).

- `web/` — одностраничная версия: `core.js` (вся математика) + `app.html` (UI) → `python3 build.py` собирает `QDebit.html`. Проверка формул: `node test.js`.
- `android/` — Kotlin/Compose. `Core.kt` — порт `core.js` 1:1, `CoreTest.kt` сверяет с эталонами веба. Данные — JSON того же формата, что экспорт веба (импорт/экспорт совместимы).
- `./build-android.sh` — тесты, сборка debug-APK, установка на телефон по USB.
- `publish-github.sh` — публикация: коммит, пуш, Pages, тег версии → релиз с APK (GitHub Actions, `.github/workflows/`). История git — в `~/dev/.qdebit.git`, отдельно от папки проекта.
- `tools/signing-setup.sh` — постоянный ключ подписи (один раз): `~/.qdebit/release.jks`, пароли в `~/.zshenv` (`QDEBIT_KEYSTORE*`), тот же ключ в Secrets репо — APK с мака и из релизов ставятся друг поверх друга. Без переменных сборка подписывается debug-ключом.
- `grafana/qdebit-dashboard.json` — дашборд (InfluxQL): дебит по скважинам, последний замер, динамика, разброс, таблица.

## База скважин (v1.1)
Профиль скважины = параметры скважины + своя система (трубы, давление, реле, насосы на графике). Замер можно привязать к скважине или сделать без привязки; привязку можно сменить в истории. Отдельные вёдра удаляются и в текущей серии, и в сохранённом замере (сводка пересчитывается).

## Типы установки (v1.2)
- `well.install`: `sub` — погружной; `surface` — поверхностный самовсасывающий / станция (труба «в скважине» = всасывающая, проверка высоты всасывания по паспорту и NPSHa = Hатм(высота) − Hпара − подъём − потери); `ejector` — поверхностный с выносным эжектором (кривые «напор на выходе» по глубинам всасывания, строки `@10`, `@20` в редакторе).
- `well.kind`: обсадная скважина / абиссинка / колодец. У скважины — «стоит насос» (`pumpId`): режим считается на вкладке «Скважина».
- Абиссинка (с 1.5.0): насос только поверхностный и всегда тянет со статики (динамики нет — труба от фильтра до насоса целиком в воде). Трение — только от зеркала до насоса (статика + отметка насоса) плюс всасывающая трасса `sys.suctLen`/`suctPipe`; глубина иглы — для справки. Труба иглы = `sys.riserPipe`. Предел иглы — по замерам: у замера поле `cav` (кавитация 0/1/2).
- Перевод старых абиссинок (однократно, `fmt` < 3): глубина иглы ← глубина забора; длина всасывающей сверх забора → трасса до насоса; если труба стояла по умолчанию (ВГП 1¼″), а Ø колонны правили — труба по этому Ø. Прежние `well`/`sys` целиком в `legacy`, остальные поля не удаляются.
- Координаты скважин (`lat`, `lon`): веб — схема с масштабом и расстояниями; Android — спутник Google или Яндекс (Яндекс в EPSG:3395 пересчитывается в веб-Меркатор построчно; тайлы кэшируются). В карточке — превью без жестов, тап открывает полноэкранную карту: скважина ставится перекрестием, «Где я» только переносит карту к телефону.

## Каталог насосов
`web/catalog.json` — единый источник: `python3 web/build.py` собирает `QDebit.html` и генерирует `android/.../CatalogData.kt`. Сейчас 879 моделей: 622 погружных, 245 поверхностных, 12 эжекторных; 188 из них — «≈ кривая» по паспортным числам, остальные по таблицам H(Q) (`src` — откуда, `note` — оговорки). Пополнение: `python3 tools/merge_catalog.py web/catalog.json research/*.json` → `python3 web/build.py` (дубли по имени и таблицы с растущим напором отсеиваются; файлы после `--force` заменяют уже имеющиеся модели — для точнее оцифрованных графиков). Свои насосы можно импортировать JSON-массивом (кнопка «Импорт насосов JSON»). Импорт понимает и формат «большого ТЗ» Perplexity (`brand`, `quality`, `hmax`, `qmax`, `qnom`, `hnom`, `diam_mm`, `power_kw`…): модели без таблицы получают кривую H = Hmax·(1 − (Q/Qmax)^n) — n=2 для погружных, 1,4 для поверхностных (калибровка по табличным кривым каталога: средняя ошибка ≈5% и ≈8% от Hmax), с номинальной точкой n подбирается по ней; такие насосы помечены «≈ кривая». Таблицы, где напор растёт с подачей, отсекаются.

## Синк (Android) через InfluxDB
- `qdebit_doc` (теги kind, id; поля json, updated, deleted; время = updatedAt) — хранилище документов, last() = последняя версия, удаление = надгробие.
- `qdebit_flow` (теги id, well, well_name; поля q, lpm, lps, n, cv, err, dyn, pump_min, note; время = момент замера) — для Grafana.
- v1: `/write` + InfluxQL (1.x, аддон HA). v2: `/api/v2/write` + Flux. Пароль/токен — только локально на телефоне.
- Веб-страница на claude.ai в Influx ходить не может (CSP), у неё — экспорт/импорт JSON и своё хранилище claude.ai.

Каталог насосов — 879 моделей (см. выше). Свои насосы — по точкам с графика паспорта или импортом JSON.

## Участок (1.6.0)
- У скважины: отметка устья `well.elev` (своя, нивелир/лазер) и `well.elevDem` (Android подтягивает по координатам: Open-Meteo / Copernicus DEM, запасной OpenTopoData SRTM 30 м; ±2–5 м). Атмосфера для всасывания считается по отметке, иначе по «высоте над морем».
- Геология: `well.aquifer` (sand | limestone; абиссинка — всегда песок), `well.aqTop` (глубина кровли песка/известняка), `well.horizon` (1–3), `well.layers` — разрез/журнал бурения `{from,to,rock,water}`.
- Вкладка «Участок»: план всех скважин (Android — карта; режимы Google спутник/гибрид/схема и Яндекс спутник/гибрид/схема), абсолютные отметки устья, зеркала (статики) и кровли, попарные перепады с уклоном зеркала и направлением потока (только для одного водоносного), профиль-разрез по выбранным скважинам (`settings.profile`).
- Веб: отметка только вручную (CSP артефакта не пускает к внешним API), план — схема без подложки.

## Модель скважины по замерам (1.7.0)
- Понижение s(Q) = B·Q + C·Q² (Джейкоб): B·Q — пласт, C·Q² — вход в скважину. B, C подбираются по замерам скважины (s/Q = B + C·Q, метод Бирсхенка) и хранятся в `well.fitB/fitC/fitN/fitQmax/fitKind`; одна точка или один расход — прямая.
- Уровень в замере: динамика с уровнемера (`dynLevel`) или по манометру (`press`, `pressAt` house|head): динамика = напор насоса по кривой − давление − трение до манометра (только погружной с выбранным насосом).
- SQE / частотник: `well.cpSet` — уставка постоянного давления; замеры с давлением ≥ уставка − 0,2 бар отбрасываются (насос на сниженных оборотах).
- Безопасный дебит ограничен честной экстраполяцией: прямая — до 1,5×, парабола — до 2× максимального расхода замеров. Время до срыва — численно с нелинейным притоком.
